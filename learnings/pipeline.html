The editorial brain + two deterministic tools

Sound design is the last authoring pass — runs only after visuals are settled in preview. Phase A separates concerns: a Python CLI builds a metadata catalog of the SFX library, a Claude skill decides which moments earn a hit and which cue type, and a second Python CLI deterministically picks files and emits a HyperFrames audio sub-composition.

Phase A scope: SFX placement only. Music beds, ambient drone, sidechain ducking, and master loudness normalization to −14 LUFS / −1 dBTP are Phase B/C.

If any of these are true mid-pipeline, you are heading toward the captchas-failure mode. Reset to maiden-video conditions and re-invoke /hyperframes with an explicit quality-bar reference.

Failure smells
  • design.md is over 60 lines
  • .hyperframes/expanded-prompt.md exists and is over 100 lines
  • compositions/ contains files marked PLACEHOLDER or [ TO BE BUILT ]
  • The Scene 1 thumbnail is a CSS primitive, not a real-looking artifact
  • The session is on turn 7+ and Scene 1 isn't built yet
  • An intermediate spec file cites a project rule then violates it
Rules going forward
01

Keep design.md ≤ ~50 lines

Palette · typography · motion · 5–6 don'ts. Not: atmosphere-layer recipes, transition tables, component formulas. Add those only after the third video proves you keep reaching for the same primitive — premature abstraction otherwise.

02

Skip expanded-prompt.md by default

Heavy scaffolding that pre-decides every scene's depth layers, verbs, and transitions. Use only when runtime is 6+ minutes and beats genuinely need explicit per-scene timing locks and you'll treat the expansion as a constraint envelope (palette + anchor timings + transition out), not a scene script.

03

Multi-composition split is fine — but build every scene

Pre-scaffolding compositions/scene-01.html…scene-11.html is neutral on creativity but creates a coordination tax. Either build all scenes in one session, or single-file composition for short videos (≤2–3 min). Don't end with placeholder stubs.

04

The first scene sets the quality bar

Generic CSS checkbox in scene 1 → generic CSS everything-else. Real-looking reCAPTCHA in scene 1 → the model carries that worldbuilding forward. When invoking /hyperframes, point at a known-good reference video as the explicit quality bar.

05

First-message specificity matters

"What's next?" lets the skill machinery default to its heaviest path. Specificity anchors a small, concrete first step and lets the build grow iteratively. The first message should name one concrete artifact, not ask for direction.

06

Pipeline-emitted artifacts respect project CLAUDE.md

Every intermediate artifact (design.md, expanded-prompt.md, per-scene spec) has to pass the same project rules the final composition does. The captchas expanded-prompt.md cited the no-chrome rule in its negative-prompt section, then prescribed VERIFICATION · 1 / 1 in beat 1. A meta-check at the end of any spec-generating step catches this.
