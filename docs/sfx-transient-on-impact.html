Where the SFX lands

SFX denote visual events, not the audio. A cue's transient lands on the impact frame — the moment the element is fully present — biased a hair late, so it is never early. You give one number, data-sfx-at-scene-ms = the impact frame; the tool aligns the sound there.

Punctuation cues (pop, tick, ding, boom, snap) land their onset on the frame. Anticipatory cues (whoosh, riser) land their peak on the frame so the swell leads in — for motion only, never for a thing appearing. Replaces the old "perceptual-landing" model.

One case — a thing appears

A card fades in. Its impact frame is the tween's start + duration — when it's fully there. The pop's audible onset lands on that frame, +12ms late: on the picture, never before it.

tl.fromTo("#card",
  { opacity: 0 }, { opacity: 1, duration: 0.5, ease: "expo.out" },
  5.0,  // start 5.0s + duration 0.5s → impact frame 5.5s
);
impact frame 5500ms (start 5000 + dur 500) → data-sfx-at-scene-ms="5500" → audible onset 5512ms (never before 5500)

You supply only the impact frame. sfx-plan reads the asset's measured onset_time_s and lands the audible start there +12ms — the never-early cushion. AV-sync research backs this: audio leading video reads as wrong far sooner than audio lagging (EBU R37, ITU-R BT.1359, ATSC all tolerate lag » lead), so a few ms late is free.

Onset vs. peak — same frame, two cue kinds

The align mode is a property of the cue. Punctuation cues land their onset on the frame. A whoosh lands its peak there — its swell leads into the moment, which is right for travel and wrong for a thing appearing.

Put a whoosh on a thing that simply appears in place and its swell reads as sound-before-visual — the Java-card bug. The fix is the right cue: pop. sfx-plan prints a pre-roll note when a peak-aligned cue precedes its own impact frame, so a misused whoosh is easy to catch.

The palette — decide by the verb

Pick the cue by what the beat is doing, never by CSS class. Each cue is a signature sound (one pinned asset, reused all video) with a fixed align.

Each cue is independent. A cue fires whenever its own visual event warrants it — regardless of any other SFX nearby. No cooldowns, no dedup, no density caps: reuse a sound as often as you like, including repeatedly within one scene. Three cards appearing = three pops, one per card, each on its own impact frame.
