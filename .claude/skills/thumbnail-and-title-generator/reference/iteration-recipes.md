# Iteration recipes

How to interpret the user's free-form feedback after a round and decide what the
next round looks like. Default: each round writes a new `round-N/` folder;
previous rounds are never overwritten.

## The default — new round, every time

Even when feedback is targeted ("just swap the punch word in A"), the default is
a new `round-N/` folder. This preserves history and makes "go back to round 2's
variant A" a one-line copy. Exception: only when the user explicitly says "edit
in place" or "just change X in this round" do you write to the current folder.

## The interpretation table

| User says | Interpretation | Action |
|---|---|---|
| "Done" / "ship it" / "export" / "approved" | Loop terminates | Run final export (SKILL.md Step 10) |
| "B's good but make A and C punchier" | Keep B, regenerate A/C harder | New round; B carried over; A/C regenerated by pushing the adjective-upgrade / sweeping reframe (`headline-recipes.md`) |
| "All three feel safe" | All too soft | New round; harder punch word + a stronger sweeping reframe on at least one; consider a hotter accent hue |
| "All three are too aggressive" | Pushed too hard | New round; soften the headline; topic-only accent; a cooler/calmer hue |
| "A's headline but B's face" | Mixed pick | New round; A's headline + B's face as the lead variant; regenerate two more |
| "Round 2's A was best — why did we move on?" | Anchor on a past variant | New round; copy `round-2/a.html` as the new lead; regenerate B/C as variations of it |
| "Try ESCAPE as the punch instead of JAVASCRIPT" | Punch/accent placement | New round; same headline + face; only the `punch accent` row moves (`accent-recipes.md`) |
| "Make the accent red" (or violet/amber…) | Accent-hue change | New round; same everything; swap the `acc-*` class. If red, note the red-sparingly guidance but honor the request |
| "Use a different face / a different emotion" | Face change | Ask the user to supply the new still; re-composite (defringe); same headline/accent |
| "Drop the pointer" / "different annotation" | Annotation change | New round; swap or remove the inline-SVG mark (`annotation-kit.md`); never substitute a scribble arrow |
| "Different title for B" | Paired-title change | New round (or in-place if asked); only the paired YouTube title changes (`title-engine.md`); thumbnail unchanged |
| "Give me a safer option in the mix" | Wants a calmer variant | New round; one variant uses a calmer headline + a cooler hue + no annotation; other two stay |

## Heuristics for vague feedback

Apply the obvious interpretation and ship the next round — don't ask for
clarification on single-word feedback.

| Vague feedback | Action |
|---|---|
| "Punchier" | Harder punch word + a bigger emotional beat in the mono tell |
| "Softer" | Topic-only accent; a cooler/calmer hue; calmer headline |
| "Bolder" | Punchier + a sweeping reframe; optionally a hotter accent hue |
| "Cleaner" | Drop the annotation + chip; one accent region only; shorter headline |
| "Try again" / "no" | Regenerate all 3 fresh; carry nothing from the previous round |

## When to ask vs. guess

Default: guess and ship — the next round is cheap. Ask one short clarifying
question only when the feedback is structurally ambiguous:

- "Make it about X" where X isn't in the title/script → "reframe the topic as X,
  or change the face/subject to X?"
- "Make the second one more like the first" → "same headline shape, same accent,
  or same face?"

## What the skill never does

- **Picks a winner.** Three variants ship to YouTube; the native A/B feature
  measures. Never say "I think B is best."
- **Declares done unilaterally.** The loop ends only when the user says "ship it"
  or equivalent. Never offer "this is good enough, shall I export?" — wait.
- **Edits old rounds.** Past rounds are immutable; fix in a new round, never by
  editing an old one.
- **Sources the face.** The user supplies + credits the image; a face/emotion
  change means asking for a new still, not finding one.
